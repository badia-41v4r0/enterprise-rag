# 0023. LLM provider registry: Ollama and OpenAI-compatible APIs, locality from the address, a default model

**Status:** Accepted (2026-11-10). Decisions taken autonomously; the ones marked **Owner review** are listed in PROGRESS.md.

## Context
Until v0.2 the chat models came from environment variables only: one host Ollama model and, optionally, one OpenRouter model. Administrators need to add providers from the admin panel (another Ollama, any OpenAI-compatible endpoint such as OpenAI, Together, Groq, vLLM or LM Studio) and to choose the model the chat uses when the user picks none, without weakening classification routing (ADR 0003), the credential store (ADR 0018), the OpenRouter rules (ADR 0016) or step-up (ADR 0019).

## Decision
- **Tables** (migration 0008): `llm_providers` (slug, name, kind, builtin, enabled, base URL, `self_hosted`, last evaluated `locality`, requested `max_classification` or NULL, `secret_name`, monthly ceiling, daily request limit) and `llm_models` (provider, model id, enabled, `env_managed`, `is_default`). A partial unique index allows at most one default model. Model ids stay `<slug>:<model>`, so stored messages and existing tests stay valid.
- **Two kinds.** `ollama` (chat through Ollama's OpenAI-compatible `/v1`, models discovered with `GET /api/tags`) and `api` (any OpenAI-compatible endpoint, models discovered with `GET /models`). A model id can always be typed by hand. Native non-OpenAI APIs (Anthropic Messages, Gemini native) are out of scope: they would need their own client and egress hook.
- **Locality is derived, never chosen.** The URL's host is resolved; the provider is `local` only if every address is loopback, private (RFC 1918, ULA), link-local or CGNAT (`100.64.0.0/10`, e.g. a tailnet); one public address makes it `cloud`. This holds for Ollama too: an Ollama on a public address is a cloud provider. Re-evaluated whenever the router is rebuilt and enforced on every request (ADR 0025).
- **Clearance is capped by locality.** Local: up to confidential. Cloud: at most `min(internal, ERAG_CLOUD_MAX_CLASSIFICATION)`. The admin may lower a provider's clearance and raise it again up to that cap, never above it (refused on save with 422; capped again when the router is built; `OpenAICompatProvider` still lowers confidential to internal for any cloud provider; `check_clearance` runs before every request). A **new non-local provider starts at `public`**; a new local one at "automatic" (confidential). When an edit moves a local provider to a public address, its clearance is reset to `public` unless the same request sets one.
- **Built-in providers.** `ollama` (from `ERAG_OLLAMA_BASE_URL`, `ERAG_LOCAL_CHAT_MODEL`) and `openrouter` (`ERAG_OPENROUTER_BASE_URL`, `ERAG_OPENROUTER_MODEL`, key in the vault as `openrouter_api_key`, env var as bootstrap fallback) are created on start-up by `erag bootstrap` and, lazily, by the first router build; idempotent. A pre-registry OpenRouter configuration (`app_settings` row `provider.openrouter`: model, on/off, ceiling) is imported when the row is first created. Their URL comes from the environment (not editable in the UI); the model named by the environment is an `env_managed` row that follows the environment (renamed in place, so a default on it is kept) and cannot be deleted, only disabled. They cannot be deleted; they can be disabled, their clearance lowered and limits lowered. `PUT /api/admin/providers/openrouter` keeps working on top of the registry row. The dev-only `claude-code` provider stays env-gated and is never stored.
- **Default model.** A (provider, model) pair stored as `llm_models.is_default`. `ModelRouter.choose` order: the user's requested model if cleared; else the default if cleared; else a cleared model, local first. The default never overrides clearance: confidential context goes to a local model even when the default is a cloud model; with no cleared model the request is refused before anything is sent. With no default ("automatic") the behaviour is exactly the previous one (prefer local). The default (its model or its provider) cannot be deleted or disabled (409, "choose another default first"); the default can only be set to an enabled model of an enabled provider.
- **Keys.** Write-only. A key entered for provider `<slug>` is stored in the vault as `provider.<slug>.api_key` (audited `secret.create/replace`), decrypted only when the router is rebuilt (`secret.use` with consumer `provider:<slug>`), never returned (the API reports `key_source`: vault/env/none), listed under "used by" in the Secrets screen and deleted with the provider. Keys are optional for both kinds (an Ollama behind an authenticating proxy, a keyless vLLM).
- **Admin API.** `GET/POST /api/admin/providers`, `PATCH/DELETE /api/admin/providers/{id}`, `POST .../test` (read-only model list, no chat completion, so it costs nothing), `POST .../discover`, `POST/PATCH/DELETE .../models[/{id}]`, `PUT /api/admin/models/default`. **Step-up** (ADR 0019) for create, delete, any change of URL, `self_hosted`, key or clearance, and for changing the default. Renaming, enabling/disabling, lowering limits, test, discover and model add/enable/remove need an admin session only (they do not open a new destination or raise what may be sent). Every action is audited (`admin.provider.*`, `admin.model.default`) with who and what, never the key (`api_key_changed: true`).
- **Hot reload.** The router cache fingerprint now covers count and latest `updated_at` of providers and models, all secrets (count, latest update, sum of versions), the legacy OpenRouter setting and the settings object; any change rebuilds the router on the next request, without a restart.
- **Chat model picker** (`GET /api/models`) returns `is_default`; the picker marks the default and shows locality and clearance for each model.

## Consequences
- A provider whose host does not resolve when the router is built is treated as cloud (the most restrictive) until the next rebuild; a provider whose address now violates its policy (an API provider that resolves to a private address, a local one that resolves to a public address) is left out of the router and shown as unavailable.
- Locality is evaluated from DNS when the router is rebuilt, not on a timer; the request-time check (ADR 0025) is what guarantees that a change between rebuilds cannot send confidential data to a public address.
- The admin cannot declare a public endpoint "local" (for example a provider with a contractual zero-retention agreement). That would need a separate, explicit trust decision; see PROGRESS.md "decisions for the owner".
