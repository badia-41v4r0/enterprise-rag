# 0026. Cost limits, token accounting, prices and a preventive worst-case check; admins may raise limits

**Status:** Accepted (2026-11-11), implements PLAN-v0.3 R6 (section 2) and decisions D2, D3. Supersedes the "the panel can only lower" rule of ADR 0024.

## Context
Until v0.2 a provider was bounded by a monthly USD ceiling that only worked when the provider reported `usage.cost`, and by a daily request cap. There was no token accounting, no price table, no `max_tokens`, no check *before* a request on what it could cost, and the panel could only lower the environment values. v0.3 removes the OpenRouter free-only rule (ADR 0028), so money must be bounded by the budget controls themselves.

## Decision
- **Token accounting.** New table `llm_usage` (provider slug, model, user, UTC day and month, requests, prompt and completion tokens, cost in USD, number of requests whose tokens were estimated), one row per (provider, model, user, day), updated with an atomic upsert (unique index with `NULLS NOT DISTINCT`, so usage without a user is one row too). Tokens come from the provider's final `usage` chunk, requested with `stream_options.include_usage` (now also for the built-in Ollama; verified against the real Ollama `/v1`); when absent they are estimated as characters / 4 and flagged. Rows hold **figures only**: never a prompt, question or answer. `provider_spend` and `provider_daily_usage` stay as the provider-level counters (ceiling and request cap), unchanged in shape, so nothing that read them breaks.
- **Prices** live on the model (`llm_models.input_usd_per_mtok`, `output_usd_per_mtok`, `price_source`), in USD per million tokens. OpenRouter prices come from its own `GET /models` (`pricing.prompt` / `pricing.completion`, USD per token) when a model is added (if a key is configured) and with **Sync prices**; negative prices (variable-price router models) are ignored. Local (unmetered) models cost 0. Other APIs: entered by the admin. An unknown price on a metered provider is shown as "unknown" in the panel and counts as 0 for the worst-case check (only the reported cost and the request cap bound it then). Actual cost = reported `usage.cost` when present, else tokens x price.
- **Limits** per provider: monthly USD ceiling and daily requests (as before), maximum output tokens per request (sent as `max_tokens`; default `ERAG_PROVIDER_MAX_OUTPUT_TOKENS`, 2048), maximum input tokens per request, tokens per day and per month, and a per-turn cap across the tool loop. Per model: overrides of max output/input tokens, and *additional* caps for that model alone (tokens per day/month, USD per month).
- **Preventive check**, before anything leaves the process, in this order (after routing has chosen a cleared provider, so clearance is first): input size, per-turn cap, provider and model budgets on the worst case `estimated input tokens x input price + max output tokens x output price` (the input estimate before sending is characters / 3, more conservative than the recording estimate), then the user's quotas (ADR 0027), then the daily request counter (counted even if the request then fails), then the egress hook and the request. A refusal names the limit that was hit and shows no usage figures of other users.
- **Raising limits (D2).** Environment values are initial defaults, not hard ceilings. An admin may set any non-negative value, higher or lower, per provider or model. Every change of a limit, price or quota requires step-up (ADR 0019) and is audited (`admin.limits.*`, `admin.price.*`, `admin.quota.*`) with the old and new value; `GET /api/admin/limits/history` and the panel show this change history. OpenRouter now also gets the default daily request cap (100) since paid models are allowed there.
- **Defaults unchanged (D3):** 0.01 USD per month and 100 requests per day per metered provider.

## Consequences
- The check is a check, not a reservation: concurrent requests can each pass it and overshoot a budget by at most (concurrency x worst case of one request). The daily request counter is still reserved atomically.
- A request that fails mid-stream is counted in the daily requests but its tokens are not recorded (as before for cost).
- `max_tokens` is now sent to every provider (2048 by default). OpenAI's newest reasoning models want `max_completion_tokens` instead; such a provider would need a gateway or a later change (decision for the owner).
- A compromised admin session can raise budgets; the change history makes it visible and the README recommends a credit limit on each provider's own key, which is the bound that holds even then.
- Tests: `tests/security/test_quotas_and_limits.py` (worst case, size, per-turn, token caps, per-model caps, step-up, history), `tests/integration/test_spend.py`, `tests/providers/test_provider_registry_real.py::test_tokens_prices_max_tokens_and_quota_with_the_real_model` (real Ollama: reported tokens recorded per user, `max_tokens` honoured, cost = tokens x price).
