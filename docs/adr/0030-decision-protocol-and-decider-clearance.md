# 0030. One decision protocol for the official and open deciders; decider clearance and egress

**Status:** Accepted (2026-11-11), implements PLAN-v0.3 sections 5 and 6 (R8) and decision D6.

## Context
The plan describes one protocol for the official Jev API and open Jev-style models: `POST /v1/systemone` with a `state` and typed `questions`. Before fixing the client I read TypeSafe's API reference (https://docs.typesafe.ai/api) and the Open-Jev repository and model card (example request `configs/example-request.json`, `jev/server.py`).

## Decision
- **Wire format (from the official reference).** Request `{"model": "jev-latest", "state": <string|object|array>, "questions": {<name>: {"type": "choice"|"score"|"noul", "instructions": ..., "criteria": ...}}}`: `choice` criteria is an object of option name to description (1 to 255), `score` criteria an array of 1 to 10 ordered levels (positions score 0, 1, ...), `noul` (the protocol's spelling of yes/no) optional `{true, false}` criteria. Response `{"model", "answers": {<name>: ...}, "usage": {"input_tokens", "output_tokens"}}`: `choice` gives `choice`, `confidence`, `probabilities`; `score` gives a probability-weighted `score`, `confidence`, `legend`, `probabilities`; `noul` gives `noul`, the probability of yes. Authentication `Authorization: Bearer <key>`. Errors 400 (`detail`) and 422 (validation list). Open-Jev servers take the same body without `model` and answer the same shape; they may omit `usage`.
- **Our four questions**: `task_type` (choice over six task types), `difficulty` (score over five levels, mapped to 1 to 5), `needs_tools` and `needs_long_context` (noul, yes when p >= 0.5). The `state` is fixed text with the metadata (classification label, tools offered, retrieved-context size) and the question between explicit markers as untrusted data.
- **Strict validation.** Every answer must have the expected type and value ranges; anything else is a decider failure (the next decider, finally the rules, decides).
- **Prompted LLM decider.** Any registry model receives a system prompt asking for exactly one JSON object with six keys; extra keys, text around the object, out-of-range values or non-integer difficulty are refused. The question is delimited and declared untrusted. Its clearance is its model's clearance (lowered further by the decider's own), and the model's provider limits apply to the router call (counted, recorded with no user).
- **Clearance (D6).** Locality comes from the address exactly as for providers (ADR 0023, 0025): private addresses only for deciders marked self-hosted (created with step-up), never metadata/unspecified/reserved addresses, HTTPS for public endpoints, re-checked and pinned on every request, no redirects. A non-local decider defaults to `public` and can be raised at most to min(internal, `ERAG_CLOUD_MAX_CLASSIFICATION`), never confidential (422 on save); a local decider may be cleared up to confidential. A decider is only called when the request's classification is within its clearance.
- **What a decider sees.** The question plus metadata; the retrieved context only for a local decider whose admin enabled "see context" (refused on save for non-local deciders, and enforced again at call time).
- **Budgets.** Each decider has its own daily request cap (counted before sending) and monthly USD budget (worst case checked before sending, reported tokens x price recorded after), defaulting for non-local deciders to the provider defaults (100 requests, 0.01 USD). Keys are write-only in the credential store (`decider.<id>.api_key`), revealed only for the call (`secret.use` by `decider:<name>`), deleted with the decider; every call is audited as `router.decider.request` (kind, locality, classification, whether context was sent; never text).
- **Test button.** `POST /api/admin/router/deciders/{id}/test` makes one minimal real call with a fixed public sample question and reports latency, tokens, cost and answers; it counts against the decider's budget.

## Consequences
- The open and official deciders share one client (`app/modelrouter/protocol.py`); unit tests of request building and response parsing use payload shapes copied from the official reference (parsing code, not a fake server).
- If TypeSafe changes the wire format, the strict parser fails closed and the rules decide.
